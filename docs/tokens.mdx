# 디자인 토큰

`tokens/tokens.json`이 Figma Tokens Studio에서 export된 [W3C Design Tokens](https://www.w3.org/community/design-tokens/) 포맷의
**유일한 소스**입니다. `@kojaem/tokens` 패키지가 Style Dictionary로 이걸 CSS 변수와 TypeScript 타입으로 변환합니다.

## 사용법

```ts
import { vars } from '@kojaem/tokens';

// vanilla-extract 스타일 안에서
style({
  backgroundColor: vars.color.fill.brand,
  color: vars.color.text.inversePrimary,
  padding: vars.spacing.padding.l,
  borderRadius: vars.radius.button.l,
});
```

`vars`는 CSS 변수 이름을 가리키는 참조 객체이고, 실제 값은 앱에서 `@kojaem/tokens/styles.css`를 import해야 채워집니다.
색상/간격/타이포/반경 값을 직접 하드코딩하지 마세요 — 항상 `vars.*`를 거칩니다.

## 계층 구조

- **Primitive**: `Purple.600`, `Gray.200`처럼 브랜드 팔레트의 원시값
- **Semantic**: `Fill/Brand`, `Text/Secondary`처럼 용도별 이름. 컴포넌트는 이 레이어만 참조합니다
- 두 레이어 모두 라이트/다크 각각 빌드되며, CSS 변수 이름 앞에는 **`mkds-`** 프리픽스가 붙습니다
  (예: `vars.color.fill.brand` → `var(--mkds-fill-brand)`)

## 라이트 / 다크

컴포넌트 코드에서 별도로 분기할 필요가 없습니다. 루트 엘리먼트에 `data-theme="dark"`를 붙이면
`[data-theme="dark"]` 스코프의 CSS 변수가 자동으로 적용됩니다.

```html
<html data-theme="dark">
```

## 토큰이 갱신되는 흐름

1. Figma Tokens Studio에서 토큰 편집 → `design/figma-token` 브랜치로 push
2. `.github/workflows/tokens.yaml`이 빌드 · 타입체크 · CSS diff를 검증
3. `main`으로 sync PR이 자동 생성됨 — merge하면 반영

## 왜 side 저장소와 다른가

side 저장소(`@sipe-team/tokens`)는 손으로 작성한 색상/타이포 TS 모듈을 토큰 빌드 결과와 병행 유지합니다.
이 저장소는 그렇게 하지 않습니다 — `tokens/tokens.json` 하나만 고치면 CSS 변수와 `vars` 타입이 함께
갱신되므로, 값이 두 곳에서 어긋날 일이 없습니다. 새 시맨틱 토큰이 필요하면 Figma Tokens Studio에서
먼저 추가하세요, TS 코드에서 값을 직접 만들지 마세요.
