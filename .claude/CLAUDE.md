# 작업 프로세스 (이 저장소 전용)

프로젝트 컨벤션은 `AGENTS.md`가 단일 소스입니다. 이 파일은 "어떻게 일할지"를 정의합니다.

## 7단계 프로세스

Figma 구현이든 버그 수정이든 아래 순서를 따르세요. 단계를 건너뛰지 마세요.

1. **이해** — 사용자 요청이 무엇을 원하는지, 어떤 컴포넌트/패키지에 해당하는지 확인. 모호하면 질문.
2. **분석** — 관련 기존 컴포넌트, 재사용 가능한 패턴, `AGENTS.md`의 관련 규칙 파악.
3. **탐색** — Figma MCP(해당 시) 또는 코드베이스를 읽어 실제 구조/토큰/variant를 확인. 추측 금지.
4. **계획** — 변경할 파일 목록, 각 파일에서 할 일을 정리.
5. **실행** — 승인 후에만 코드 작성(아래 "코드 작성 전 승인" 참고).
6. **검증** — `pnpm build`/`pnpm test`/`pnpm biome check` 중 관련된 것 실행, Storybook에서 시각 확인.
7. **완료** — 변경 요약, `.changeset/` 필요 여부 확인.

## 코드 작성 전 승인 필수

Figma 구현, 새 컴포넌트 생성, 여러 파일에 걸친 리팩터링은 **계획(4단계)까지 먼저 사용자에게 보여주고 승인을 받은 뒤** 코드를 작성합니다. 오타 수정처럼 명백히 사소한 변경은 예외입니다.

## 금지사항

| 금지 | 근거 |
|---|---|
| Figma Properties에 없는 variant/state 임의 생성 | `AGENTS.md` 컴포넌트 구현 금지사항 |
| 원본 텍스트/라벨 임의 변경 | `AGENTS.md` 컴포넌트 구현 금지사항 |
| 컴포넌트 폴더를 손으로 복사해서 새 컴포넌트 생성 | `AGENTS.md` 프로젝트 구조 — `pnpm create:component` 사용 |
| `.css.ts`에 색상 리터럴(hex/rgb/hsl) 하드코딩 | `AGENTS.md` 스타일링 규칙 |
| 컴포넌트 루트에 고정 width px 하드코딩 | `AGENTS.md` 컴포넌트 너비 규칙 |
| `tokens/tokens.json`, `contract.css.ts`를 Figma 싱크 없이 손으로 수정 | `AGENTS.md` 디자인 토큰 — 유일한 소스 원칙 |
| 승인 없이 여러 파일 코드부터 작성 | 위 "코드 작성 전 승인 필수" |
| Story/테스트 없이 컴포넌트 변경 완료 보고 | `AGENTS.md` 테스트 가이드라인 |
